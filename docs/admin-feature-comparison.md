# Admin feature comparison

Last reviewed: 2026-09-13

## Scope

This document compares the administration features in the archived SvelteKit/Supabase application with the active Next.js/Hono application. It focuses on the platform administrator and the organization-management tools reachable from that area.

The legacy reference is `archive/svelte-supabase-v1` in the root worktree. The earlier `next-strapi-v1` generation is not used as the parity target because the SvelteKit generation contains the more complete admin implementation.

### Status meanings

- **Complete:** A usable UI and its supporting server behavior exist.
- **Backend only:** The active application has an API/domain implementation, but no admin UI exposes it.
- **Partial:** Some of the flow exists, but it is incomplete or differs materially from the legacy behavior.
- **Not implemented:** No substantive implementation exists in that application.

## Current admin routes

| Route                               | Purpose                                                |
| ----------------------------------- | ------------------------------------------------------ |
| `/admin`                            | Redirects to the implemented organization section.     |
| `/admin/organizaciones`             | Lists organizations and their current state.           |
| `/admin/organizaciones/nueva`       | Creates an inactive organization.                      |
| `/admin/organizaciones/[id]`        | Shows organization information and lifecycle controls. |
| `/admin/organizaciones/[id]/editar` | Updates organization name and description.             |

## Suggested implementation order after the initial slice

1. Add global category administration because the active backend already supports it and it has few dependencies.
2. Add organization members and invitations using the active single-organizer role model.
3. Add organization event and race management using global and organization categories.
4. Decide whether event-specific categories, event images, and rich-text descriptions should return before extending the schema.
5. Add dashboards only after concrete metrics and operational decisions are defined.
